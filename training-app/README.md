# トレーニングコーチ（トレーニング管理アプリ）

ジムでのトレーニングを、体調・疲労・時間・過去の実績からメニュー自動作成し、トレーニング中の記録・進捗管理・有酸素タイマー・成長分析まで行う PWA（ホーム画面に追加して使う Web アプリ）です。主な利用端末は iPhone を想定しています。

ChatGPT 上で運用していたパーソナルトレーニング支援を、独立したアプリとして実装したものです。

## 設計の全体像

メニューの生成と調整は端末内のルールベース処理です。通常の利用に LLM API の接続は不要です。画面下のタブは「ホーム／トレーニング／履歴／分析／みんな／設定」の6つです。

| 層 | 役割 | 主な実装 |
|---|---|---|
| 画面・操作 | 初回ヒアリング、記録、選択式の調整、履歴、分析 | `src/app/`、`src/components/` |
| メニュー作成 | 店舗の器具・希望・体調・履歴から種目や負荷を決定 | `src/lib/planner/` |
| 記録編集 | セットの完了、実績の確定、並べ替え、終了処理 | `src/lib/workout/` |
| 端末内保存 | 記録・設定・店舗別器具を IndexedDB に保存 | `src/lib/db/` |
| 任意の共有 | 完了済み記録の要約を API 経由で保存・閲覧 | `src/lib/share/`、`src/app/api/share/` |
| PWA・タイマー | 画面のキャッシュ、時刻基準のタイマー復元 | `public/sw.js`、`src/lib/timer/`、`src/hooks/useTimer.ts` |

詳細なトレーニング記録は端末内に置き、共有時だけ要約をサーバーへ送ります。端末間で詳細記録を自動同期する機能はありません。

## 主な機能

| 機能 | 概要 |
|---|---|
| トレーニング開始ヒアリング | 店舗 / 時間 / 体調 / 筋肉痛・疲労（部位・強さ） / 痛み / 重点部位 / 有酸素（なし・ウォーキング・ランニング）を選択式で確認。前回値を初期値にし、変更可能。メモに「次から〇〇」と書くと今後の希望として保存 |
| はじめてのヒアリング | 初めて使う人は、パスワード入力・「はじめに」（名前と共有だけ）の直後に表示（スキップ可。以前から使っていてまだ答えていない人は初めてのトレーニング開始時）。経験（初期選択なし。選ばなければ経験による補正はしない）・目標（複数）・左右差・時間・きつさの好み・器具（マシン/ダンベル）・有酸素・多めに/控えめにしたい部位・やりたい/やりたくない種目・普段から気をつけたい痛み・自由記述の希望を質問（スキップ可）。体格の初期値は20歳・体重は男性65kg／女性55kg。2ページ目で「これまでに行っていたトレーニング種目」を種目一覧（全件）から選び（一覧の上の「＋ 種目を追加」で一覧に無い標準の種目を戻したり、新しく作ったりして選べる）、分かれば重量・回数を入力（無い人は2ページ目だけスキップ可）。選んだ種目は自動作成で選ばれやすくなり（自動作成の枠に無い種目も候補になる）、アプリにまだ記録が無いときは入力した重量の約9割から始める。答えは「メニューの希望」として毎回のメニュー作成に反映 |
| メニューの希望 | やりたくない種目は自動作成で選ばず同じ枠の別種目に、控えたい部位は減らし、はじめての人は種目数・セット数を抑えてマシン優先、軽め希望は回数多め・セット少なめ、追い込み希望は主要種目のセットを増やす、有酸素なしはその時間を筋トレに回す、普段の痛みは毎回除外判定に使う。作成時の要約に「希望を反映：…」と表示。設定画面の一番上「ヒアリング結果（メニューの希望）」で全項目を確認でき、「ヒアリング結果を編集する」から変更できる。伝えた希望の履歴も残る |
| トレーニングを調整（ホーム） | 選択肢から選ぶ方式（自由入力なし）。「久しぶりのトレーニング（1〜2週間／2〜4週間／1〜2か月／2か月以上）」を選ぶと次に作るメニューを軽めに、「今後の希望を変える」でヒアリング結果の編集へ |
| 店舗（LifeFit 以外のジムも） | 標準は LifeFit の3店舗だが、設定の「店舗」からどんなジムでも登録できる（使わない標準店舗は「表示しない」にできる。記録は残る）。追加した店舗は器具が「未確認」から始まり、「店舗の器具」で「すべて「ない」にする」→ある器具だけ「ある」にすると早い。器具を「ある」にすると、その器具を使う標準の種目（バーベルスクワット・デッドリフトなど）が種目一覧に加わり、自動作成の候補にもなる（各枠にフリーウェイト・スミス・プレート式・自重の種目を用意）。実際に行った種目の器具は保存時に自動で「ある」になる。トレッドミル・バイクを「ない」にした店舗では有酸素を入れない。追加した店舗は開始前の質問の既定になり、記録・履歴の絞り込み・分析・共有・JSON の入出力でも名前と色が保たれる |
| 自分でメニューを入力 | ホームの「メニューを自分で入力して記録」（またはヒアリング画面の「メニューを作らず自分で入力する」）から、店舗を選んで空のトレーニングを開始。「＋ 種目を追加」「＋ 有酸素を追加（トレッドミル／バイク）」で自由に組み立てて記録できる。開始時に今日または過去の日付を選べる。履歴の「＋ 過去の記録を追加」からも入力でき、保存後は「修正する」で変更可能。種目を追加すると前回の記録と重量の進め方から重量・回数が入る。自分で入力した回数がそのまま目標になる。自分で組んだメニュー（直近8週間・最大6回）でよく行う種目は自動作成でも選ばれやすくなり（自動作成の枠に無い種目も候補になる）、並び順も自分のメニューに合わせる |
| 有酸素を押し付けない | ヒアリングの有酸素の初期値は「なし」。「ウォームアップのバイク：使う／使わない」も聞く（任意）。答えていなければ、その日に有酸素「なし」を選んだ人と、直近の記録（2回以上）でバイクを一度も行っていない人にはバイクを入れず、その分を筋トレに回す。開始前の質問の有酸素の初期値は、保存済みの継続する希望 → 前回の選択 → 記録（走っていればランニング、歩いていればウォーキング）→ なし。明示的な希望がなくトレッドミルを一度も行っていない人は「なし」から（選び直せば入る） |
| 記録から好みを学ぶ | おすすめを押し付けず、直近8週間・最大8回の記録（自動作成のメニューも含む。実際にセットを終えた種目・完了した有酸素だけ）から好みを学ぶ。よく行う種目は選ばれやすく（自分で入力したメニューの種目は特に）、並び順は「AとBを両方行った日のうちAが先だった回数」の多数決で決める（1回だけ順番が違った日に引きずられない）。行ったことのない種目は器具の種類（ダンベル→マシン など）の順に合わせて置く。セット数はその種目の直近3回の中央値（記録が無ければ標準値）。バイク・トレッドミルは、筋トレの前／途中／後のどこで行っていたかの多数決で置く。ダンベル優先・定期的に入れたい種目などの設定は学んだ好みより優先 |
| ルールベースのメニュー作成 | 履歴・経過日数・疲労・体調・店舗の器具・時間・前回重量から種目/セット/重量/回数/休憩を提案。別店舗の重量は「参考値」として扱い、実回数が未報告なら達成とみなさず据え置き |
| 重量の進め方 | 予定したセットを**すべて**目標回数で終えたときだけ前に進める（途中でやめた・届かなかったときは据え置き、2回続けて届かなければ約10%下げる）。初心者は重量を1段階ずつ、中級者以上・軽め希望は回数を上限まで増やしてから重量を上げる。新しい重量でこなせる回数を前回の結果から推定し、届きそうにないときは先に回数を増やす（刻みが大きすぎる器具では、上限の回数を3回続けて達成するまで上げない）。上級者・50歳以上・軽め希望は続けて達成してから上げる。体重・性別・年齢・経験から初めての種目の重量の目安を出す。種目は 下半身の複合 / 上半身の複合 / 単関節 / 体幹 に分けて上げ幅と回数の範囲を決める。前回より重い重量・多い回数のセットには注意書きを表示。負荷の進行ルールにはシミュレーションテストを用意（`src/lib/planner/progression.test.ts`）。これは実装の検証であり、実際の利用者の筋力向上を検証した結果ではない |
| 重量の刻み | 店舗・器具ごとに何kgずつ重量を変えられるかを設定（設定 → 店舗の器具、またはトレーニング中の「フォーム・メモ」）。メニューの重量・± ボタン・下げるときの丸めに使う |
| 久しぶりのトレーニング | 前回から2週間以上空いたとき、または「トレーニングを調整」の期間選択・当日のメモで「久しぶり」「2週間ぶり」「1か月休んでた」などと伝えたときは、空いた期間に応じて重量を約10〜35%下げ（4週間以上ならセット数も減らす）、その日は重量・回数を上げない。トレーニング中は「久しぶりのトレーニングだった」から期間を選ぶと、まだ始めていない種目の重量とセット数を下げる |
| メインのトレーニング UI | 種目カード（折りたたみ / フォーカス）、大きな完了チェック、重量・回数の素早い編集、セット追加・削除（完了済みは確認 + 元に戻す）、未実施セットの除外、完了チェックで「目標どおり実施」として記録（届かなかったときは回数を実際の回数に直してからチェックすると「未達成」として記録。次回の重量の判断に使う）、片手種目の左右別記録、フォームの説明とメモは「フォーム・メモ」を押したときだけ表示、見出しの長押しドラッグで種目・有酸素の並べ替え（Notion の行の移動のような操作。有酸素を種目の間へ動かすことも可能。画面の端で止めると自動スクロール）、バイク・トレッドミルも削除可能、進捗バー（セット数・種目数・残り種目・推定残り時間） |
| 自動保存・再開 | 変更のたびに IndexedDB に保存。アプリを閉じても途中から再開。終了・保存後も履歴から修正可能。画面上部と下部の「キャンセル」でその日のトレーニングを破棄できる |
| 有酸素管理 | バイク / トレッドミルの区間表（時間・運動・速度・傾斜）。ランニングは前回実績から連続走行時間を段階的に延長（速度と時間を同時に大きく上げない）。計画と実績を区別して保存 |
| タイマー | 「インターバル」（運動・休憩・回数・準備を自由に設定）、「タイマー」（分・秒を設定する通常のタイマー）、バイク、トレッドミルの4種類。バイク・トレッドミルは作られた区間をそのまま使え、「時間・負荷を変更」で区間ごとの時間とレベル（バイク）・速度と傾斜（トレッドミル）を自分で変えてセットできる（メニューの有酸素と紐づくときはメニューの計画にも反映）。プリセットや設定を選ぶとセットされるだけで、スタートは自分で押す。スタートしたタイマーは履歴に残り、履歴をタップするとすぐ呼び出せる（名前も付けられる）。一時停止 / 再開 / リセット / 次区間へ / ±30秒。音・振動（対応端末）・画面消灯防止。スリープ後も開始時刻から正しく復元。セット完了後の休憩タイマーはトレーニング画面に自動で表示（±10秒で調整。時間は設定画面で「種目ごと」または30秒〜3分から選べる。各種目の最終セットの後は表示しない） |
| 履歴・分析 | 午前6時区切り（Asia/Tokyo）のトレーニング日。種目ごとの重量推移（店舗別系列）、総セット数、店舗別、ランニング推移、週間・月間、休息日カレンダー。JSON / CSV エクスポート、JSON インポート |
| 店舗の追加 | 標準の LifeFit 3店舗に加えて、設定画面で店舗を追加・名前変更・削除できる。追加した店舗の器具は「すべて未確認」か、既存店舗の設定をコピーして始める。削除しても記録は残り、記録には店舗名が保存される |
| 店舗別器具管理 | 店舗ごとに「ある / 未確認 / ない」を編集。「ない」にすると次回以降のメニューから自動除外 |
| トレーニングを調整（トレーニング中） | 選択肢から選ぶ方式（自由入力なし）。「残り時間が少ない（10〜45分）」「疲れている部位がある（部位を選ぶ）」「マシンが使えない（種目を選ぶと同じ部位の種目に置き換え）」「重量を上げてもいい？」「ランニングをやめてウォーキングにする」「今日は有酸素をやめる」「久しぶりのトレーニングだった」「今後この種目は外したい」。提案は「予定」にだけ反映され、実績は変更しない |
| 初回設定（はじめに） | 表示名と共有のオン・オフを決め、その後のヒアリングで目標・経験・メニューの希望を設定（スキップ可）。全員が空の履歴から始まる |
| 作成者の記録の復元 | 作成者の過去の記録（2026-09-20〜10-16、12回分）はサーバー側にだけ置き、復元コード（`OWNER_RESTORE_CODE`）を知っている本人だけが `/restore` から取り込める。他の利用者には表示されない |
| 種目一覧 | 設定の「種目一覧」で標準・自作のすべての種目を確認でき、各種目の × で削除できる（トレーニング中の「種目を追加」からも ×）。削除した標準の種目は自動作成と種目の追加に出なくなり、「削除した標準の種目」からいつでも元に戻せる。過去の記録は種目名ごと残る |
| 自分の種目 | カタログに無い種目を作成・編集・削除できる（種目名・記録の仕方〔重量×回数／回数のみ／時間〕・器具・鍛える部位・片手片脚・セット数・目標回数・重量の刻み・休憩・フォームのメモ）。トレーニング中の「種目を追加」から作ってそのまま追加することも可能。「メニューの自動作成に含める」をオンにすると自動作成の候補になる。削除しても端末内の過去の記録には種目名が残る。共有先には種目名を送らず、種目数・セット数などの要約だけを表示する |
| 標準の種目一覧 | LifeFit 一乗寺店・東山二条店の器具の種目（器具ごとに1種目）、ベンチプレス、ダンベルの代表的な5種目（ダンベルベンチプレス・ワンハンドダンベルロウ・ダンベルショルダープレス・サイドレイズ・ゴブレットスクワット）、作成者が行っていた種目、今後追加する予定だった種目にしぼる。それ以外（デッドリフト・ハックスクワット・ダンベルフライなど）は「一覧に入っていない標準の種目」から一覧に加えられる |
| ダンベル種目 | ダンベルベンチプレス・インクラインダンベルプレス・フライ・ワンハンドロウ・ショルダープレス・サイドレイズ・リアレイズ・シュラッグ・ゴブレットスクワット・ランジ・ルーマニアンデッドリフト・キックバック・フレンチプレス。通常はマシン優先で、マシンが無い店舗や「ダンベル優先」の人に提案 |
| バーベル・プレート式の種目 | LifeFit 公式の店舗ページのマシンリスト（一乗寺店・三条大橋店、2026-10-20 確認）の器具を店舗の器具に登録し、ベンチプレス・バーベルスクワット・デッドリフト・ベントオーバーロウ（パワーラック）、スミスマシンのベンチプレス・スクワット・ショルダープレス、EZバーカール、プレートチェストプレス・コンバージングチェストプレス・プレートショルダープレス・プレートラットプルダウン・45度レッグプレス・ハックスクワット・ロータリートーソー・チンニング・ディップス・レッグレイズ（チェア）・デクラインシットアップを標準の種目にした。重量はバーやプレートを含めた合計で記録。部位ごとの自動作成の枠にも候補を用意し、店舗の器具・種目一覧・希望に応じて選ぶ。種目の追加や自分で組むメニューでも使える |
| 時間だけ記録 | ホームの「時間だけ記録」から日付・店舗・開始／終了時刻だけを入力。種目・セットなしの完了済み記録として保存し、履歴に時刻を表示。合計は0分より長く6時間以内。共有時は時間で活動量を表示する |
| トレーニング時間 | セットの完了時刻から、マシン・ダンベル・自重・有酸素の時間と合計を自動計算。終了時と履歴で修正可能。共有している人は時間も「みんな」に表示（直近7日の合計も） |
| 人ごとの目標 | 設定画面でいつでも変更可能。メニュー作成に反映（有酸素の長さ、筋力重視の回数、優先部位、お気に入り種目、片手種目の左右の進め方） |
| みんなの記録（共有） | 各自が共有のオン・オフを選択。共有するのは「誰が・いつ・どこで・どれくらい」（表示名・日付・店舗・時間の内訳・種目数とセット数・有酸素の分数）だけで、種目名・重量・回数・体調・痛み・メモは共有しない。「みんな」タブでは直近2週間の表（行＝人、列＝日、色＝店舗、濃さ＝量）と最近のトレーニング（量の横棒）、各人のページでは直近28日のカレンダーと回ごとの量を表示。以前の形式で送られていた詳細はサーバーで要約だけにして返し、各端末が次に開いたときに要約だけで送り直す。オフにするとサーバー上の記録は削除。作成者は「みんな」タブの「アカウントを整理する（作成者のみ）」で復元コード（`OWNER_RESTORE_CODE`）を入力すると、不要なアカウントを削除できる（自分のアカウントは対象外） |

## 技術スタック

- Next.js 16（App Router, Turbopack）/ React 19 / TypeScript
- Tailwind CSS v4（ダークモードは `data-theme` 属性 + システム設定）
- Dexie（IndexedDB）… ローカル保存。記録・設定は `id`、店舗別器具・汎用データは `key` を主キーとし、`updatedAt` を保持
- Recharts … 分析グラフ
- Vitest（単体）/ Playwright（E2E, iPhone 14 ビューポート）

## セットアップ

```bash
cd training-app
npm ci
npm run dev          # http://localhost:3000
```

本番ビルドと起動:

```bash
npm run build
npm start            # http://localhost:3000
```

> Service Worker（オフライン用）は本番ビルド（`npm run build && npm start`）でのみ登録されます。開発サーバーでは登録しません。

### iPhone での利用（ホーム画面に追加）

1. 同じ Wi-Fi 上の PC で `npm run build && npm start -- -H 0.0.0.0` を実行し、iPhone の Safari で `http://<PCのIPアドレス>:3000` を開く

## 使い方

1. **ホーム** → 「トレーニング開始」
2. **今日のコンディション** を選択 → 「メニューを作成」
3. **トレーニング画面**
   - 種目カードのヘッダーをタップで折りたたみ。「この種目に集中」で 1 種目だけ大きく表示
   - 各セット：−/＋ または直接入力で重量・回数・秒数を編集し、✓ で実施済みとして記録。🗑 で削除、− で「未実施として除外」。片手・片脚種目は左右別に入力できます
   - ✓ を付けると、その欄の回数・秒数を実績として記録します。目標に届かなかった場合は、実際の回数に直してからチェックしてください。チェックを外すと実績が消え、再度チェックした値で記録できます。時間種目はセット内のタイマー終了でも完了になります
   - 休憩タイマーは通常のセット完了後に表示されます（その種目の最終セット後と時間種目は対象外）
   - 「フォーム・メモ」でフォーム・シート設定・注意点・メモを表示
   - 有酸素カードは順番が来るまで折りたたみ（最初の未完了種目と、その前のウォームアップだけ開く）。「時間・負荷を変更」で区間ごとの時間・負荷を変えられ、「タイマーを開始」で区間タイマーへ。「計画どおり完了にする」で計画の内容がそのまま実績になり、違ったときだけ「実績を入力」で直す。手入力する実績はトレッドミルが合計・走行時間・速度、バイクが合計時間のみ
   - 「トレーニングを調整」で「残り時間が少ない」「マシンが使えない」などを選ぶとメニューを組み直す
   - 「トレーニングを終了・保存」→ 未完了セットは未実施として除外されます（履歴から「修正する」で変更可）
4. **履歴** で過去の記録を確認・修正。**分析** でグラフ。**設定** で店舗の器具・除外種目・テーマ・エクスポート。

### 過去の記録・時間だけの記録

- **種目も記録する**：ホームの「メニューを自分で入力して記録」または履歴の「＋ 過去の記録を追加」→ 日付・店舗を選択 → 種目や有酸素を追加 → 実施したセットに ✓ → 終了・保存。未来の日付は選べません。進行中の記録がある場合は、先に保存するか、確認画面で破棄して始めます。
- **時間だけ記録する**：ホームの「時間だけ記録」（`/log-time`）→ 日付・店舗・開始／終了時刻 → 「この時間で記録する」。種目やセットを作らず、直接履歴に保存します。ホームに開始ボタンが出ない場合は進行中の記録を先に終了してください。日付は今日までで、午前6時より前の時刻は選択したトレーニング日の翌朝として扱います。
- 時間だけの記録も、共有をオンにしていれば「みんな」の活動量に反映されます。有酸素を実施したかは分からないため、有酸素の習慣判定には含めません。

### 1 日の区切り

トレーニング日は **午前 6 時〜翌午前 6 時（Asia/Tokyo）** です。例：10/14 01:00 のトレーニングは 10/13 として記録されます（`src/lib/date/trainingDay.ts`）。

### タイマーの制約（iOS）

- iPhone の Safari / ホーム画面アプリでは、**画面がスリープしたりアプリが裏に回ると、音や振動は鳴りません**（iOS の制約。バックグラウンド通知は保証できません）。
- 対策として「画面を消灯しない」（Screen Wake Lock, iOS 16.4+ / HTTPS が必要）を既定で有効にしています。トレッドミルのホルダーに置いて画面を表示したままにしてください。
- 音は最初のタップ（開始ボタン）で有効化されます。iPhone のサイレントスイッチが ON だと Web Audio の音は鳴らないことがあります。
- スリープしても、タイマーは「開始時刻」基準で計算しているため、再表示時に正しい経過時間・区間に復元されます。
- iOS Safari は振動 API（`navigator.vibrate`）に非対応です（Android Chrome では動作）。

## データとバックアップ

| 保存・出力先 | 含まれる内容 | 範囲・制約 |
|---|---|---|
| IndexedDB（`training-coach`） | トレーニング記録、設定・プロフィール、店舗別器具、汎用データ | 端末・ブラウザ側の保存領域。タイマーの進行状態は別途 localStorage に保存 |
| JSON エクスポート | 全トレーニング記録、店舗別器具、追加店舗 | `workouts`・`storeEquipment`・`customStores`。プロフィール・共有トークン・目標・メニューの希望・自作種目の定義・タイマー設定などは含まない |
| CSV エクスポート | 筋トレのセット一覧と有酸素一覧 | 筋トレは完了済み記録の完了・非除外セット。有酸素は完了済み記録の各有酸素項目を計画／実績の別列で出力。アプリへの取り込み用ではない |
| 共有サーバー | 表示名と完了済み記録の要約 | 詳細な重量・回数やヒアリング内容を復元するためのバックアップではない |

**設定 → データ** から JSON / CSV をエクスポートできます。機種変更時は旧端末で JSON を書き出し、新端末でインポートしてください。同じ ID の記録と店舗別器具は上書きされ、追加店舗は未登録の ID だけ追加されます。JSON に含まれない設定は新端末で再設定が必要です（`src/lib/export.ts`、`src/components/settings/SettingsView.tsx`）。

サイトデータの削除や端末の変更に備え、JSON は端末の保存領域とは別の場所にも保管してください。共有は要約の送信であり、詳細記録の自動バックアップや端末間同期ではありません。

## テスト

```bash
npm run typecheck     # tsc
npm run lint          # eslint
npm test              # Vitest（日付境界・プランナー・目標・タイマー・編集・意図解析・分析・エクスポート・共有）
npm run test:e2e      # Playwright（本番ビルド後に実行。npm run build が必要）
```

E2E は Chromium に iPhone 14 の画面・端末設定を適用して実行します（iPhone 実機や Safari / WebKit の検証ではありません）。テスト項目には、初回設定、店舗の追加と削除、3人での記録共有（共有した人だけ表示・オフで削除・保存時の自動送信）、開始→メニュー作成→セット追加/削除/重量編集→再読み込みで復元→保存→履歴、選択式の「残り時間が少ない → 20分」による短縮、過去の日付の入力、時間だけの記録、タイマーの一時停止/再開/復元、器具の除外、PWA（manifest / Service Worker）、ダークモードがあります。テストファイルの存在と実行結果は別であり、実行した環境で成否を確認してください。

`playwright.config.ts` は Linux では既定で `/opt/pw-browsers/chromium` を使い、`PW_CHROMIUM` で実行ファイルを上書きできます。Playwright が管理する Chromium を使う場合は、`npx playwright install chromium` を実行し、Linux では `PW_CHROMIUM='' npm run test:e2e` として既定パスを無効にします。

テストサーバーの自動起動コマンドは POSIX シェル形式です。Windows の PowerShell では、ビルド後に別ターミナルで次のように起動し、既存サーバーに接続します（ローカルのテスト専用設定）。既存の環境変数や `.env.local` に本番の共有保存先・パスワードを設定していない、テスト専用の作業コピーを使ってください。

```powershell
# ターミナル1（training-app 内）
$env:OWNER_RESTORE_CODE = 'e2e-owner'
$env:SHARE_STORE = 'file'
$env:SHARE_FILE = '.data/e2e-share.json'
$env:ALLOW_PUBLIC_SHARE = '1'
$env:APP_PASSWORD = ''
npm start -- -p 3100 -H 127.0.0.1

# ターミナル2（training-app 内）
npx playwright install chromium
$env:PW_NO_SERVER = '1'
npm run test:e2e
```

`ALLOW_PUBLIC_SHARE=1` はアクセス保護なしで共有を許可するテスト用の例外です。公開環境には設定しないでください。テスト終了後はテスト用ターミナルを閉じてください。

## 設計上の方針（仕様からの要点）

- **予定と実績を分け、完了操作で確定**：`reps/seconds` は入力欄の値、`actualReps/actualSeconds` は実績です。自動作成時の回数は `plannedReps` に残し、達成判定に使います。完了チェックで実績が未設定なら入力欄の値を実績にコピーし、未完了に戻すと実績を消します。実績がない取り込み記録などを達成扱いにはしません。メニュー調整のパッチは完了済み実績を変更しません（`src/lib/workout/edit.ts`、`src/lib/coach/applyPatch.ts`）。
- **別店舗・別マシンの重量**：同一負荷とみなさず、参考値として 1 段階軽くし、カードに「参考値」ラベルを表示。グラフは店舗ごとに系列を分けます。
- **器具の有無を推測で確定しない**：利用実績のある器具は「ある」、不明は「未確認」として表示。「ない」にすると次回以降除外。追加した店舗の器具は最初はすべて「未確認」です。
- **時間と希望に応じた量の調整**：自動作成の種目数は最大12種目で、時間や経験によって上限を下げます。セット数は履歴の中央値または標準値に体調・希望などの補正を加えるため、一律3セット上限ではありません。有酸素の有無も当日の選択・希望・履歴から決めます（`src/lib/planner/index.ts`）。
- **バードドッグ**はカタログに含めていません。**片手ダンベルハンマーカール**は直近 2 回入っていなければ優先度を上げます。

## 外出先（別の Wi-Fi / モバイル回線）から使う：無料で公開する

自宅 PC で動かす方法は同じ Wi-Fi でしか使えません。どこからでも使うには、無料ホスティングに公開します。**Vercel の Hobby プラン（個人・非商用は無料）**が最も簡単です。

### 1. アクセス保護を有効にする（推奨）

公開 URL は誰でも開けるため、共有パスワードで保護します。環境変数 `APP_PASSWORD` を設定すると、保護対象の画面と API で認証が必要になります（ログイン Cookie の有効期間は1年間。Cookie にはハッシュを保存）。詳細な記録は各端末の IndexedDB に保存し、共有をオンにした場合は要約を共有サーバーにも保存します。ログイン画面・インストール用の静的ファイルなどは保護の対象外です。

### 2. Vercel にデプロイする

1. [vercel.com](https://vercel.com) に GitHub アカウントでサインアップ（無料）
2. **Add New → Project** → この GitHub リポジトリ（`1took0/Yuto_Takeshige`）を Import
3. 設定画面で次を指定
   - **Root Directory**: `training-app`
   - **Framework Preset**: Next.js（自動検出）
   - **Environment Variables**:
     - `APP_PASSWORD` = 好きなパスワード（推奨。記録共有を使う場合は必須）
4. **Deploy** を押す。数分で `https://<プロジェクト名>.vercel.app` が発行されます
5. iPhone の Safari でその URL を開き、パスワードを入力 → 共有ボタン → **ホーム画面に追加**

HTTPS は Service Worker や画面消灯防止（Wake Lock）を利用するための前提です。実際の利用可否はブラウザの対応状況にも依存します。オフラインではキャッシュ済み画面を利用し、共有 API は通信が必要です。以後は GitHub の対象ブランチに push するたびに自動で再デプロイされます（Vercel の Production Branch 設定で、このアプリのブランチを指定してください）。

## 複数人での利用と記録共有

同じ URL を複数人で使えます。詳細記録は各自の端末に保存され、共有をオンにした人の完了済み記録の要約がサーバーに送られ、アクセスできる利用者の「みんな」タブに表示されます。

### 仕組み

- 初回起動時に各端末でプロフィール（ランダムな ID と秘密トークン）を作成します。サーバーにはトークンのハッシュを保存し、通常の更新・削除で userId とトークンを照合します。共有パスワードは共通の入口の保護で、利用者ごとのログインアカウントではありません。作成者の復元コードによる管理者削除は別の経路です。
- 共有されるのは表示名と、完了した記録の要約（日付・店舗・トレーニング時間の内訳・種目数とセット数・有酸素の分数）だけです。種目名・重量・回数・記録のメモ・ヒアリング内容（体調・疲労・痛み）は送りません。以前の版で詳細つきで送られた記録も、サーバーは要約だけを返し、各端末は次に開いたときに要約だけで送り直します。
- 作成者は「みんな」タブの「アカウントを整理する（作成者のみ）」で復元コードを入力すると、不要なアカウントを削除できます。
- 共有をオフにする操作では、サーバー上のプロフィールと記録の削除が成功してから、端末の共有設定をオフにします。通信できない場合は操作が完了しないため、接続後に再試行してください。
- 通信できないときは変更を保留し、次回起動時や再接続時に自動で送信します。
- 通常運用では、**保存先とアクセス保護（APP_PASSWORD）の両方**を設定すると共有が有効になります。`ALLOW_PUBLIC_SHARE=1` はテスト用の例外で、公開環境では使用しません。

### 共有の保存先を用意する（無料）

Vercel で公開している場合：

1. Vercel のプロジェクト画面 → **Storage**（または Marketplace）→ **Upstash for Redis** を選び、**Free** プランでデータベースを作成してプロジェクトに接続
2. 接続すると `KV_REST_API_URL` / `KV_REST_API_TOKEN`（または `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN`）が自動で環境変数に追加されます
3. `APP_PASSWORD` が設定されていることを確認して再デプロイ

Upstash の無料プランはクレジットカード不要で、データ容量 256MB です。数人〜十数人のトレーニング記録なら十分収まります。Free プランのままなら課金は発生しません。無料枠の上限を超えた場合は共有の読み書きが一時的に止まりますが、記録自体は各端末に残ります。有料プランへの切り替えは手動操作が必要なので、誤って課金されることはありません。最新の無料枠は [Upstash の料金ページ](https://upstash.com/pricing/redis) で確認してください。

自宅 PC で動かす場合は、ファイルに保存できます。

```bash
APP_PASSWORD=好きなパスワード SHARE_STORE=file npm start
```

### 作成者の記録の復元

作成者の過去の記録は、復元コードを知っている人だけが取り込めます。サーバーの環境変数 `OWNER_RESTORE_CODE` に好きなコードを設定し、作成者本人の端末で一度だけ、**設定 → データ →「復元コードで記録を取り込む」**（`https://<公開URL>/restore`）を開きます。

> iPhone では、ホーム画面に追加したアプリと Safari とでデータが共有されません。Safari で取り込んでからホーム画面に追加すると、ホーム画面版には記録がありません。**先にホーム画面に追加し、そのアプリの中で**ログイン・初回設定・復元を行ってください。

コードを入力すると12回分が取り込まれ、目標も作成者の設定になります（チェックを外せば目標はそのまま）。コードを知らない人には取り込めず、記録データは公開される JavaScript にも含まれません。

### 利用者を増やす手順

1. URL と APP_PASSWORD を伝える
2. 各自が iPhone の Safari で開いてパスワードを入力し、ホーム画面に追加
3. 「はじめに」で表示名と共有のオン・オフを決め、その後のヒアリングで目標・経験・メニューの希望を設定（スキップ可）。あとから設定画面で変更できます

## 自分のAIにメニューを相談する

### 店舗ごとの重量調整

重量の基準は **利用者の端末内の店舗・種目ごとの実績** です。同じ店舗に重量の記録があれば、それを優先して既存の達成状況に応じた調整を行います。他店舗の新しい重量を平均・換算して上書きすることはありません。画面には、この店舗の基準と他店舗の参考記録を区別して表示します。

同店舗の重量が未記録の場合は、他店舗の直近の重量を参考に控えめな仮の目安を使います（アシスト種目は補助を増やします）。実際に使った重量・回数に直して完了チェックし、トレーニングを終了すると、次回その店舗の基準になります。他店舗の実績は変更されません。同店舗の最新記録に重量がない場合は、それより前の有効な重量を据え置きで参照します。未完了・除外セットを重量の基準にはしません。

「フォーム・メモ」の重量の刻みは、入力確定時に「設定 → 店舗の器具」と共通の店舗・器具設定へ保存し、保存完了を表示します。同店舗で同じ器具を使う種目の ± ボタンと次回のメニュー作成に反映します。他店舗の刻み、作成済みの重量、過去の実績は変更しません。記録重量と刻みが合わないときは、重量を勝手に丸めず維持し、刻みの確認を案内します。AIへの相談文にも、選択した履歴の範囲から店舗別の重量記録と調整方針を出力します。

### AIと中長期の方針を決めて取り込む

ホームまたは設定の **「AIにメニューを相談」**（`/ai-coach`）から、希望・参考店舗の器具・直近4/8/20回までの終了済み記録を相談文にまとめます。今日だけのメニューではなく、今後継続するメニュー作成方針を各自のAIチャットで相談する機能です。

1. 合わない点や理想を入力し、参考にする店舗と出力範囲を選びます。保存済みの体格・痛み・自由記述メモ・店舗の実名は初期状態では含めません。進行中のメニューは出力しません。
2. 「相談文を作成」で確認してコピー、または `.txt` で保存し、ChatGPT・Claude・Gemini・Grokなどに貼り付けます。相談文には現在の設定、記録の読み方、対応する調整項目、アプリへ戻すJSON形式も含まれます。APIキーは不要で、アプリからAIへの自動送信はありません。
3. AIと会話して方針を決め、「アプリに反映する方針を出して」と伝えます。
4. 返されたJSONをアプリに貼り付け、「変更内容を確認」。日本語の変更前・変更後を確認して「この方針を次回以降に反映」を押すと保存されます。文章を貼るだけでは設定は変わりません。
5. 新しく自動作成するメニューから適用します。過去の記録・進行中のメニュー・店舗の重量実績は変更しません。保存後に方針を手修正していなければ、直前の取り込みを元に戻せます。

調整対象は、目標・重点部位・定期的に入れたい/避けたい種目、採用された筋トレ種目の優先順、種目別のセット数・回数/秒数・休憩、普段の時間、器具や強度の好み、重量と回数の進め方（標準/慎重/自動増加停止）、トレッドミル（なし/歩行/走行）、ウォームアップのバイク（あり/なし）です。種目の採用は保証せず、痛み・疲労・器具・時間の制約を優先します。重量は引き続き店舗ごとの実績と刻みに基づきます。回数を種目別に固定した場合は、以前の回数目標の達成による自動増量を止めます。時間はカタログ値に基づく概算です。

曜日別の分割・周期化、固定kg、バイクを主運動にする計画、有酸素の細かな区間や配置は自動取り込みに対応していません。未対応のキーや未知の種目ID、範囲外の値は保存せず、修正を案内します。初回ヒアリングは従来のままです。形式・優先順位・保存仕様は [AI方針の取り込み設計](docs/ai-policy.md) を参照してください。

予定と実績、未報告とゼロ、左右別の値、未完了・除外・スキップを区別して出力します。プロフィールの氏名・利用者ID・共有トークンは出力しません。入力文・種目名・メモに含まれる個人情報の自動除去はないため、コピー前に確認してください。相談文の希望・取り込んだ設定・取り消し用の直前の設定は端末内に保存し、既存の記録用JSONバックアップには含まれません。
